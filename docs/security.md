# Security

What the product does by design, where the controls live, and what remains
the operator's job.

## Controls

| Concern | Control | Where |
|---|---|---|
| Code execution from data | No configuration is generated as code and nothing is `exec`ed; settings are data validated by Pydantic | `oss_core.config` |
| Network exposure | Only Caddy publishes a port; Caddy terminates TLS (TLS 1.2 and 1.3; `SEMASCOPE_TLS` picks Caddy's internal authority, ACME or your certificate files) and redirects plain HTTP sent to that port. `SEMASCOPE_ADMIN_ALLOW` limits `/admin/` to the address ranges listed (everyone by default). Three networks: Caddy shares `edge` with the server only, so the proxy reaches nothing else; Tika, which parses untrusted files, sits alone on `extract`, an internal network (no route out) shared with the worker and the cli only, so it cannot reach Valkey, Solr, Neo4j, PostgreSQL or the internet; the rest is on the default network. The observability profile publishes Grafana and Flower on `127.0.0.1` only, behind a password | `compose.yaml`, `compose.observe.yaml`, `deploy/caddy/Caddyfile` |
| Store authentication | PostgreSQL and Neo4j use the generated passwords; Solr runs with basic authentication (`blockUnknown`), set up from `SOLR_PASSWORD` on first start and on existing installs at the next `./oss up`; Solr counts as healthy only once anonymous requests are refused. Valkey requires `VALKEY_PASSWORD` (`requirepass`, read from a file inside the container rather than the command line) and counts as healthy only once anonymous clients are refused; `./oss up` generates the password for installs made before it existed. Tika has no authentication; only the worker and the cli can reach it (`extract` network) | `deploy/solr/init-security.sh`, [deploy/solr](https://github.com/rdb420/semascope/blob/main/deploy/solr/README.md), `compose.yaml` |
| Secrets | Generated by `oss init` into `.env` (gitignored, mode 600), or with `--secrets-dir` into one file each, mounted as Docker secrets by `compose.secrets.yaml`; any setting can be read from the file a `<NAME>_FILE` variable names. Never in images. Outside debug mode the server, workers and beat refuse to start when a required secret (`SEMASCOPE_SECRET_KEY`, `POSTGRES_PASSWORD`, `NEO4J_PASSWORD`, `SOLR_PASSWORD`, `VALKEY_PASSWORD`, `SEMASCOPE_ADMIN_PASSWORD`) is empty or a placeholder such as `change-me`, or when the optional API token or pseudonym key is a placeholder. No secret has a default in the settings or the compose files (Grafana and Flower in the observability profile need `GRAFANA_PASSWORD`, which `oss init` also generates). `./oss rotate` changes the secrets in the stores and `.env` together. Source credentials (an S3 secret key) stay in the source settings, are read when an item is fetched and never travel in queued tasks. Nothing the server shows or writes down echoes a credential: one redaction module masks values whose key names a credential (secret, password, token, API key, authorization, cookie, private key, ...) or that a connector declares as one (`credential_settings`), the password in any URL and credential-named query values, in source settings (editors see them masked; readers and curators get no source settings at all), collection settings, source errors, webhook addresses, audit details and the admin, whose forms show masks and keep the stored secret when a mask is sent back (a webhook's signing secret is never shown). A CLI token generated at first start is written to `/data/cli-token` (mode 600), never to the log; the server's access log leaves out query strings, which carry feed tokens, and the server's, workers' and beat's log lines mask the password of any URL, tracebacks included | `oss init`, `oss rotate`, `compose.secrets.yaml`, `oss_core.config`, `settings.py`, `connectors/s3.py`, `redact.py`, `logredact.py`, `api/root.py`, `entry.py` |
| Remote model services | The `remote` runtime sends `SEMASCOPE_REMOTE_API_KEY` (or a per-stage key) as a bearer token to the embedding, entity and parsing services; document text leaves the host to those services, so point them only at endpoints you control or trust, over TLS or a private network | `config.py`, `docs/operations.md` |
| Authentication | Local accounts (Django), created by an administrator only: there is no sign-up form, and allauth's local sign-up is closed when single sign-on is on. Bearer tokens stored hashed. Optional OpenID Connect, which creates an account on first sign-in only while `SEMASCOPE_OIDC_AUTO_SIGNUP` is true and gives it `SEMASCOPE_OIDC_DEFAULT_ROLE` (default `none`: no role of its own). Session cookies are Secure outside debug mode, CSRF enforced on every session-authenticated POST and on sign-in itself (so another site cannot sign a browser into an account of its choosing). Repeated failed sign-ins lock the account (`SEMASCOPE_LOGIN_MAX_FAILURES`, 5) and the client address (`SEMASCOPE_LOGIN_MAX_FAILURES_PER_IP`, 50) out for `SEMASCOPE_LOGIN_LOCKOUT_S` (900 s), the right password included, on every sign-in path (API, Django admin, allauth); the API answers 429 with Retry-After. Every API route needs a signed-in user except sign-in itself; the Reconciliation API is anonymous only when `SEMASCOPE_RECONCILE_PUBLIC=true` (for OpenRefine, which cannot send a token) | `api/auth.py`, `api/accounts.py`, `ratelimit.py`, `api/reconcile.py`, `signup.py` |
| Authorisation | Roles per collection or global (reader, curator, editor, admin; staff are admin) are checked on every route that reads or writes collection data. Reading needs `reader` on the collection; lists, search in every mode, facets, exports, saved-search alerts, the graph, curation queues and stats cover only readable collections. `SEMASCOPE_DEFAULT_ROLE` is what signed-in users get on collections they hold no role on: by default `none`, so reading is per collection and a user without a role reads nothing; `reader` opens reading to every signed-in user ([Roles](concepts.md#roles)). Vocabulary that is not collection data (packs, concepts, query tags, reconciliation) needs a role on at least one collection: an account with no role reads nothing, since a list pack can name people. Staff-only Cypher and SPARQL consoles are read-only (the Cypher console in a read transaction), EXPLAIN-checked, row-capped and time-limited. A table-driven test calls every route as seven kinds of user (anonymous, signed in without a role, a reader of another collection, reader, curator, editor, staff), and a route without a rule fails it | `api/access.py`, `oss-server/tests/test_authz_matrix.py` |
| Request limits | Per-user rate limits on the expensive routes, counted per bearer token (each token on its own) or session user, per client address when anonymous, in Valkey so every server process shares them: searches and views 600 a minute, exports 60 an hour, list search 60 an hour, graph routes 240 a minute, the consoles 60 a minute, queued jobs (bulk tagging, reindexing, source runs, pack imports and activations) 120 an hour, uploads 600 an hour, reconciliation 600 a minute; `SEMASCOPE_RATE_LIMITS` changes them (`export=10/h`) or turns them `off`. A refused request answers 429 with Retry-After, and the CLI waits and retries. The limits fail open while Valkey is unreachable. Caps: an uploaded file `SEMASCOPE_UPLOAD_MAX_MB` (512), any other request body `SEMASCOPE_REQUEST_MAX_MB` (10), both 413; Caddy refuses upload requests above `SEMASCOPE_UPLOAD_LIMIT` (2 GB) and other bodies above 32 MB; a reconciliation batch holds at most 50 queries of 500 characters and 25 candidates each (400 otherwise); query tags read the first 12 words; search rows, pages and facets are capped as in [Search](search.md) | `ratelimit.py`, `api/root.py`, `api/reconcile.py`, `settings.py`, `deploy/caddy/Caddyfile` |
| Audit log | An append-only table of who did what, when and from where: sign-ins (success, failure, lockout refusal) and sign-outs; users' staff, superuser and active flags, passwords (that they changed, never the hash), e-mail and permissions; collection roles; API and feed tokens; collections and their settings; sources; webhooks; pack versions created, activated and removed, and the pack imports and activations asked for; exports; bulk tagging, reindexing, uploads and annotation imports; annotation deletions; Cypher and SPARQL console queries. Changes made in the Django admin or a shell are recorded as well as those made through the API. Each entry holds the actor and channel (session, token, admin, anonymous, system), the client address and user agent, the target and a redacted detail: field names for settings, secrets and URLs, never their values. The application cannot change an entry (and on PostgreSQL a trigger refuses UPDATE); a daily task removes entries older than `SEMASCOPE_AUDIT_RETENTION_DAYS` (365; 0 keeps them). Staff read it at `GET /api/audit` and in the admin (read-only); each entry is also one line on the `semascope.audit` logger, for shipping elsewhere. Audit entries are not webhook events: webhooks send to outside addresses, and entries carry account names and addresses | `oss_server/audit`, `api/audit.py` |
| Search queries | Field names a request names (filters, facets, the histogram) must be plain names (letters, digits, `_`, `-`) of a known field or an allowed dynamic kind (`*_s`, `*_ss`, `*_b`, `*_paths`, dates for the histogram), or they are dropped; every value placed in a Solr query, delete-by-query included, is one quoted term; collection slugs are Django slugs (422 otherwise), checked again wherever a slug names a folder (the upload area), so `.`, `..` and path separators never reach a path | `api/search.py`, `clients/solr.py` (`quote_term`), `api/schemas.py` |
| Custom index fields | A source's custom fields are accepted only as `x_<name>` (lower-case letters, digits, `_`, `-`) and never replace the index's own fields (`id`, `collection_s`, `uri_s`, the text, the tags and the other fields of the documents schema), so no source can make its document replace another's | `stages/index.py` |
| Collection settings | A collection's `settings.pipeline` may only tune its stages (sizes, caps, retries, optional work, pseudonymisation); service addresses, credentials, Solr collection names and secrets come from the deployment, so collection settings cannot send the workers or their credentials elsewhere. Other keys are refused by the API and ignored by the workers | `pipeline/overrides.py` |
| Source paths | File-reading sources (filesystem, mail, archive, table, RDF files) read only under `SEMASCOPE_SOURCE_ROOTS` (default: `/import`, mounted read-only, and the demo corpus in the image); upload sources only under their collection's upload area. Paths are resolved through symlinks and checked when a source is created, when it runs, and when a file is fetched | `connectors/guard.py` |
| Outbound requests | Every URL a source, a user or a document supplies goes through one guarded client: web pages, robots.txt and sitemaps, feeds and the pages they link, SPARQL endpoints, S3 endpoints (each boto3 request is sent through it) and webhook deliveries. It reaches only globally routable unicast addresses (`ipaddress.is_global`): loopback, private, carrier-grade NAT (100.64.0.0/10), link-local, documentation, multicast, reserved and unspecified addresses are refused, IPv4-mapped and NAT64 (64:ff9b::/96) addresses are judged by the IPv4 address inside, and 6to4 and Teredo addresses are refused; a host whose name resolves to several addresses is refused if any of them is refused. Each new connection resolves the host name once, checks every address, and connects to a checked address, while the Host header and TLS (SNI and certificate verification) keep the host name; a name that resolves to a different address at connection time (DNS rebinding) therefore cannot reach a private one. Each request and each redirect is also checked before it is sent, redirects stop after 10, and environment proxies are not used for these requests (a proxy would resolve the name itself). `SEMASCOPE_ALLOWED_PRIVATE_HOSTS` lets an operator name internal hosts (names or CIDR ranges). Webhook URLs must be http(s) with a host (422 otherwise), and a webhook never follows a redirect: the delivery is reported as failed. The guarded client sets connect (10 s), read, write and pool timeouts, and a response other than an S3 object download must finish within 15 minutes. Bodies are capped on the bytes received, while streaming, before they are buffered: a declared length over the cap is refused before the body is read. Web, feed and SPARQL use the source's `max_bytes` (50 MiB by default; never above 1 GiB: refused when a source is created above it, clamped at run time), robots.txt 512 KiB, webhook answers 64 KiB, S3 listings 8 MiB, and an S3 object is capped by the bytes read (512 MiB by default, or the source's `max_bytes`), whatever the listing said. The web connector respects robots.txt. Services the operator configures (Tika, MinerU, and the embedding, entity and extraction providers) use a separate client with the same timeouts and a body cap (256 MiB; 1 GiB for Tika) and no redirects, but no address check: their URLs come only from the deployment's settings, never from a source, a collection's settings or a user, and they normally sit on a private network | `connectors/guard.py` (`guarded_client`, `guard_s3_client`, `service_client`), `connectors/web.py`, `tasks.deliver_webhooks` |
| Untrusted files | Tika runs in its own container with a task timeout; archives are streamed to disk member by member, never held in memory, and expanded within limits counted on the bytes actually decompressed: a member size limit, one byte budget for everything expanded from an archive across all nesting levels (100 times its size, at most 4 GiB), a member count across all levels and a nesting depth, and a zip member whose header claims a ratio above 100 is skipped; XML through defusedxml; JSON-LD files (packs and RDF sources) must carry their context inline, and a remote `@context` or `@import` is refused, never fetched; previews rendered by pypdfium2 and Pillow, no shell-outs | `connectors/archive.py`, `connectors/rdf.py`, `oss_core.pack`, `stages/*` |
| Browser | React escapes output; Solr snippets are escaped before `<mark>` is restored; HTML previews are not rendered as HTML. The server's pages (the UI, the admin, the sign-on pages) carry a Content-Security-Policy: scripts from the site only (no inline script, no eval), images and tile requests from the site and the configured map-tile server, form posts to the site and the sign-on issuer, no plugins, no framing; originals keep their own sandboxing policy. Caddy adds HSTS, Permissions-Policy (no camera, microphone, location, payment, USB, serial or Bluetooth), Cross-Origin-Opener-Policy, nosniff and Referrer-Policy once each, replacing what Django sets, and removes the Server header | `security.py`, `deploy/caddy/Caddyfile` |
| Errors | An unexpected error answers 500 with a reference that appears in the server log beside the traceback; store errors (Solr, Neo4j, the pack store) are logged under a reference, never echoed, including in console and similar-document answers. `/healthz` answers 503 without its database and says nothing else about the stores (`oss doctor` checks them with credentials) | `api/errors.py`, `urls.py` |
| Personal data | A collection can pseudonymise named-entity keys in the graph. Deleting a document removes it from the `documents` and `chunks` collections in Solr, from the graph (its edges, its properties and the entities only it mentioned; a bare node stays only to carry curator decisions), and its blob, previews and work file from disk unless another document has the same content, and keeps the Postgres row as a tombstone with its content cleared. Deleting a source or collection removes its documents from Solr, the graph (curator decisions included) and the disk, with the uploaded files; a daily sweep removes files no document uses. Backups keep what they hold. `no-store` collections are planned | `stages/graph.py`, `tasks.delete_document`, `pipeline/retention.py` |
| Supply chain | Locked dependencies (`uv.lock`, `pnpm-lock.yaml`); release images built in CI with provenance and SBOM; a clean-room check script compares the tree with the legacy code base | `.github/workflows`, `scripts/cleanroom_check.py` |

## Operator's job

- Put the stack behind your own TLS certificate and host name (`SEMASCOPE_HOST`,
  `SEMASCOPE_TLS`) when it leaves a laptop, and consider
  `SEMASCOPE_ADMIN_ALLOW` for `/admin/`.
- Read the audit log (`GET /api/audit`, the admin) or ship the
  `semascope.audit` log lines to your log store; it is kept for
  `SEMASCOPE_AUDIT_RETENTION_DAYS`.
- Turn on `SEMASCOPE_RECONCILE_PUBLIC` only if OpenRefine must reach the
  packs without a token, knowing that it publishes the active packs'
  vocabulary.
- Rotate secrets with `./oss rotate`, which changes each one in its store
  and in `.env` together and keeps every other setting; with Docker secrets
  (`--secrets-dir`), change them in the stores and the files by hand
  ([Secrets](operations.md#secrets)). `oss init --force` only rewrites
  `.env`, for a stack whose volumes are about to be recreated.
- Decide who reads what. With the default `SEMASCOPE_DEFAULT_ROLE=none`
  give each user a role on the collections they may see (or a global role);
  `reader` lets every signed-in user read every collection.
- Keep `SEMASCOPE_SOURCE_ROOTS` pointing at folders meant for indexing, and
  list in `SEMASCOPE_ALLOWED_PRIVATE_HOSTS` only internal hosts that sources and webhooks
  should reach.
- Back up with `./oss backup` and keep `.env` beside the backup.
