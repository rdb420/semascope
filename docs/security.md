# Security

What the product does by design, where the controls live, and what remains
the operator's job.

## Controls

| Concern | Control | Where |
|---|---|---|
| Code execution from data | No configuration is generated as code and nothing is `exec`ed; settings are data validated by Pydantic | `oss_core.config` |
| Network exposure | Only Caddy publishes a port; Solr, Tika, Neo4j, PostgreSQL and Valkey stay on the compose network; Caddy terminates TLS | `compose.yaml`, `deploy/caddy` |
| Store authentication | PostgreSQL and Neo4j use the generated passwords; Solr runs with basic authentication (`blockUnknown`), set up from `SOLR_PASSWORD` on first start and on existing installs at the next `./oss up`; Solr counts as healthy only once anonymous requests are refused. Valkey requires `VALKEY_PASSWORD` (`requirepass`, read from a file inside the container rather than the command line) and counts as healthy only once anonymous clients are refused; `./oss up` generates the password for installs made before it existed. Tika has no authentication and relies on the compose network | `deploy/solr/init-security.sh`, [deploy/solr](https://github.com/rdb420/semascope/blob/main/deploy/solr/README.md), `compose.yaml` |
| Secrets | Generated by `oss init` into `.env` (gitignored, mode 600); never in images. Outside debug mode the server, workers and beat refuse to start when a required secret (`SEMASCOPE_SECRET_KEY`, `POSTGRES_PASSWORD`, `NEO4J_PASSWORD`, `SOLR_PASSWORD`, `VALKEY_PASSWORD`, `SEMASCOPE_ADMIN_PASSWORD`) is empty or a placeholder such as `change-me`. No secret has a default in the settings or the compose files (Grafana in the observability profile needs `GRAFANA_PASSWORD`, which `oss init` also generates). Source credentials (an S3 secret key) stay in the source settings, are read when an item is fetched, never travel in queued tasks, and the API returns them masked; account identifiers (an S3 access key id, a user name) are masked too for users below `editor` on the collection | `oss init`, `oss_core.config`, `settings.py`, `connectors/s3.py`, `api/root.py` |
| Remote model services | The `remote` runtime sends `SEMASCOPE_REMOTE_API_KEY` (or a per-stage key) as a bearer token to the embedding, entity and parsing services; document text leaves the host to those services, so point them only at endpoints you control or trust, over TLS or a private network | `config.py`, `docs/operations.md` |
| Authentication | Local accounts (Django), created by an administrator only: there is no sign-up form, and allauth's local sign-up is closed when single sign-on is on. Bearer tokens stored hashed. Optional OpenID Connect, which creates an account on first sign-in only while `SEMASCOPE_OIDC_AUTO_SIGNUP` is true and gives it `SEMASCOPE_OIDC_DEFAULT_ROLE` (default `none`: no role of its own). Session cookies are Secure outside debug mode, CSRF enforced on every session-authenticated POST. Every API route needs a signed-in user except sign-in itself and the Reconciliation API, which is public by design (it exposes the active packs' vocabulary, no documents) | `api/auth.py`, `api/accounts.py`, `api/reconcile.py`, `signup.py` |
| Authorisation | Roles per collection or global (reader, curator, editor, admin; staff are admin) are checked on every route that reads or writes collection data. Reading needs `reader` on the collection; lists, search in every mode, facets, exports, saved-search alerts, the graph, curation queues and stats cover only readable collections. `SEMASCOPE_DEFAULT_ROLE` is what signed-in users get on collections they hold no role on: by default `none`, so reading is per collection and a user without a role reads nothing; `reader` opens reading to every signed-in user ([Roles](concepts.md#roles)). Staff-only Cypher and SPARQL consoles are read-only, EXPLAIN-checked and row-capped. A table-driven test calls every route as six kinds of user, and a route without a rule fails it | `api/access.py`, `oss-server/tests/test_authz_matrix.py` |
| Search queries | Field names a request names (filters, facets, the histogram) must be plain names (letters, digits, `_`, `-`) of a known field or an allowed dynamic kind (`*_s`, `*_ss`, `*_b`, `*_paths`, dates for the histogram), or they are dropped; every value placed in a Solr query, delete-by-query included, is one quoted term; collection slugs are Django slugs (422 otherwise), checked again wherever a slug names a folder (the upload area), so `.`, `..` and path separators never reach a path | `api/search.py`, `clients/solr.py` (`quote_term`), `api/schemas.py` |
| Custom index fields | A source's custom fields are accepted only as `x_<name>` (lower-case letters, digits, `_`, `-`) and never replace the index's own fields (`id`, `collection_s`, `uri_s`, the text, the tags and the other fields of the documents schema), so no source can make its document replace another's | `stages/index.py` |
| Collection settings | A collection's `settings.pipeline` may only tune its stages (sizes, caps, retries, optional work, pseudonymisation); service addresses, credentials, Solr collection names and secrets come from the deployment, so collection settings cannot send the workers or their credentials elsewhere. Other keys are refused by the API and ignored by the workers | `pipeline/overrides.py` |
| Source paths | File-reading sources (filesystem, mail, archive, table, RDF files) read only under `SEMASCOPE_SOURCE_ROOTS` (default: `/import`, mounted read-only, and the demo corpus in the image); upload sources only under their collection's upload area. Paths are resolved through symlinks and checked when a source is created, when it runs, and when a file is fetched | `connectors/guard.py` |
| Outbound requests | Web, feed, SPARQL-endpoint and S3-endpoint sources and webhook deliveries reach only globally routable unicast addresses (`ipaddress.is_global`): loopback, private, carrier-grade NAT (100.64.0.0/10), link-local, documentation, multicast, reserved and unspecified addresses are refused, IPv4-mapped and NAT64 (64:ff9b::/96) addresses are judged by the IPv4 address inside, and 6to4 and Teredo addresses are refused; checked on every request and redirect (`SEMASCOPE_ALLOWED_PRIVATE_HOSTS` lets an operator name internal hosts). Webhook URLs must be http(s) with a host (422 otherwise), and a webhook never follows a redirect: the delivery is reported as failed. Web, feed and SPARQL responses are read with a size cap (`max_bytes`, 50 MiB by default for web and feeds; a source's `max_bytes` can never exceed 1 GiB: refused when a source is created above it, clamped at run time), requests time out, and the web connector respects robots.txt. The address check resolves the host name before the request, so DNS that changes between the check and the connection is not covered | `connectors/guard.py`, `connectors/web.py`, `tasks.deliver_webhooks` |
| Untrusted files | Tika runs in its own container with a task timeout; archives are streamed to disk member by member, never held in memory, and expanded within limits counted on the bytes actually decompressed: a member size limit, one byte budget for everything expanded from an archive across all nesting levels (100 times its size, at most 4 GiB), a member count across all levels and a nesting depth, and a zip member whose header claims a ratio above 100 is skipped; XML through defusedxml; JSON-LD files (packs and RDF sources) must carry their context inline, and a remote `@context` or `@import` is refused, never fetched; previews rendered by pypdfium2 and Pillow, no shell-outs | `connectors/archive.py`, `connectors/rdf.py`, `oss_core.pack`, `stages/*` |
| Browser | React escapes output; Solr snippets are escaped before `<mark>` is restored; HTML previews are not rendered as HTML | `oss-web` |
| Personal data | A collection can pseudonymise named-entity keys in the graph. Deleting a document removes it from the `documents` and `chunks` collections in Solr, from the graph (its edges, its properties and the entities only it mentioned; a bare node stays only to carry curator decisions), and its blob, previews and work file from disk unless another document has the same content, and keeps the Postgres row as a tombstone with its content cleared. Deleting a source or collection removes its documents from Solr, the graph (curator decisions included) and the disk, with the uploaded files; a daily sweep removes files no document uses. Backups keep what they hold. `no-store` collections are planned | `stages/graph.py`, `tasks.delete_document`, `pipeline/retention.py` |
| Supply chain | Locked dependencies (`uv.lock`, `pnpm-lock.yaml`); release images built in CI with provenance and SBOM; a clean-room check script compares the tree with the legacy code base | `.github/workflows`, `scripts/cleanroom_check.py` |

## Operator's job

- Put the stack behind your own TLS certificate and host name (`SEMASCOPE_HOST`,
  Caddy config) when it leaves a laptop.
- Rotate `.env` secrets by re-running `oss init --force` (it keeps every
  other setting) and recreating the
  volumes, or by editing `.env` and restarting; database passwords also need
  changing in the stores.
- Decide who reads what. With the default `SEMASCOPE_DEFAULT_ROLE=none`
  give each user a role on the collections they may see (or a global role);
  `reader` lets every signed-in user read every collection.
- Keep `SEMASCOPE_SOURCE_ROOTS` pointing at folders meant for indexing, and
  list in `SEMASCOPE_ALLOWED_PRIVATE_HOSTS` only internal hosts that sources and webhooks
  should reach.
- Back up with `./oss backup` and keep `.env` beside the backup.
